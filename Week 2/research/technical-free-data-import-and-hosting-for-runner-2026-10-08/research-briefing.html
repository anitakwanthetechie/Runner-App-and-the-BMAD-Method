Executive summary

Yes, runner-app can launch for $0. The runner imports files they export themselves. The plan in brief: - Import (R1): FIT files first, read in the browser with the MIT-licensed fit-file-parser [22]. GPX and TCX as a fallback. - Load (R3): session RPE (rating of perceived exertion: effort rating × minutes) as the main load measure for runs and swims alike [27][29]. - Hosting (R5): a static site on GitHub Pages or Cloudflare [45][47]. - Storage (R6): data in IndexedDB, with an export/import backup file. - Your decision (R7): where swim cross-training sits in MoSCoW, once the sports-science research run is back.

The findings behind the answer:

  1. There's no free live data connection, so files are the only route in.
    • Apple: Apple Health has no web API [62]. A native app needs the US$99/year program to be demoed publicly [3][4].
    • Strava: the API now needs a paid Strava subscription just to create an app [13]. Its login needs a server-side secret [15], and its terms cap caching at 7 days [14].
    • What's left: the runner already uploads to Strava, which can export each activity as its original file. Strava's website and Runkeeper both offer file export [18][21]. Unverified Whether export works on free accounts is unconfirmed. Medium confidence.
  2. Your swim requirement decides two things.
    • The file format: pool swims lose their data in GPX and most of it in TCX [18][20]. FIT is likely the best format for them. Low confidence Low confidence: forum-level evidence only.
    • The load measure: session RPE is the only measure in this research that works the same way for runs and swims, with or without heart rate, and needs no fitness test [27][29]. Inference This is an inference from each measure's required inputs. HR-based TRIMP (training impulse, a heart-rate load score) can add a second signal, but only with a separate swim max heart rate, which is about 7 bpm lower than in running [33]. No source supports simply adding run and swim training-stress scores together.
  3. Safari can silently delete local-first data. iPhone Safari deletes stored data after 7 days without a visit unless the app is on the Home Screen [57]. The browser's request to keep data permanently (persist()) can't be relied on there [58]. So a backup file and an "Add to Home Screen" step are requirements, not nice-to-haves.

Biggest caveat: several details need a 30-minute hands-on test on your own phone and accounts rather than more web research: - Is Strava's per-activity export still free on non-subscriber accounts? - Which swim fields does an Apple Watch FIT export actually contain? - Can a free Apple Shortcut export workouts?

1. Apple data access

No web route into Apple Health exists, and no native route is $0 and demoable at the same time.

  • Web access. Apple's HealthKit documentation lists only native platforms (iOS, iPadOS, macOS, watchOS, visionOS) and no web or JavaScript one [62]. Apple's own developer forum has an unanswered 2020 question on exactly this [1]. Pages that describe an "Apple Health Web API" come from content-farm domains with no Apple backing, and this research rejects them [2]. Verified Verified. High confidence.
  • Native app. The Apple Developer Program costs US$99/year [3]. A free Apple Account can still build to your own device with Xcode. Limits: provisioning profiles expire after 7 days, at most 3 devices, at most 3 apps per device, and no TestFlight or App Store [4]. Apple's capability table allows HealthKit on free accounts [5]. Verified Verified. Even so, a free native build is a personal tool and cannot be a public demo.
  • Apple's own export. "Export All Health Data" produces export.xml plus a workout-routes/ folder of GPX files [6]. Unverified The source could not be re-checked. Medium confidence. The files are large: a blogger calls it "a huge file" [7], and one user reports 1 GB of XML [8], so an in-browser importer would have to read them in pieces (stream). Low confidence Low-medium confidence. This research did not confirm whether swim lengths and running dynamics (power, ground contact time and so on) are in export.xml. That needs a hands-on test.
  • Single-workout export apps. Some exist, and the useful ones cost money. HealthFit is US$6.99 [9]. RunGap's export needs a subscription (US$4.99/quarter or US$14.99/year) [10]. "GPX Export" is listed as free but exports routes only [11].
  • Apple Shortcuts. A "Find Health Samples" action exists [12]. No source confirms that it can read whole workouts and save them to a file. A hands-on test can settle this.

2. Import formats, Strava and swim data

File import is the only $0 path that works on a static site. FIT is the format to support first, because only FIT is likely to keep pool-swim detail.

  • Strava API is closed to a $0 static app. Two blockers settle it:
    • Strava's developer docs state that "A Strava subscription is a prerequisite for creating an app" [13]. The API Policy (effective June 1, 2026) adds subscription requirements for small apps [14].
    • The OAuth token exchange needs the app's client secret [15]. A site with no backend would expose that secret.
    • Further limits if the API is revisited:
      • New apps start in single-player mode (developer only), then get a 10-athlete cap until Strava reviews them [13].
      • The API Agreement allows data to be shown only to the athlete who owns it [16]. The Policy caps caching at 7 days and bans use in any AI application [14].
      • Rate limits: the default is 200 requests per 15 minutes and 2,000 per day overall, of which reads are 100 per 15 minutes and 1,000 per day. The higher limits (400 per 15 minutes, 4,000 per day) apply only after an app is upgraded to 10 athletes [17][13]. Verified Verified. The two pages describe different tiers.
  • Strava export (the free alternative). Export works on the Strava website only, not in the mobile app. "Export Original" returns the file as it was uploaded, often FIT. GPX export needs GPS data, so pool swims export as unusable GPX [18]. TCX is available through a URL suffix [18]. A bulk "Download your data" archive contains one file per activity plus activities.csv [18][19]. This research didn't confirm whether free accounts can use per-activity export.
  • Runkeeper. The web export gives GPX files plus CSV summaries. Apple Watch-only and manual activities appear only in the CSV [21]. Runkeeper's help page [21] doesn't say whether export is free.
  • Swim data by format. A Garmin forum thread reports that TCX files don't export stroke and swim-efficiency data [20]. GPX and TCX files of activities without GPS carry no GPS points [63], and FIT pool swims carry lap records [64]. Low confidence Low confidence: user forums only, with no official vendor statement. The likely ranking for pool swims is FIT first, then TCX, then GPX, which keeps nothing. This research did not confirm the exact FIT fields for pool lengths and strokes.
  • Browser parsers.
    • fit-file-parser: MIT license, last release September 22, 2026 [22]. This is the safe default.
    • Garmin's official @garmin/fitsdk runs in the browser [23] and is royalty-free [24]. Its license, though, forbids "distribut[ing] … the Licensed Technology … to any third party" [24]. Bundling it into a public web app may conflict with that clause. Unverified Ambiguous; needs a human read.
    • gpxparser hasn't had a release since 2021 [25].
    • @tmcw/togeojson (BSD-2 license, last release May 2025) converts GPX and TCX to GeoJSON [26].

3. Cross-sport training load measures

Session RPE (effort rating × minutes) is the simplest measure that works for every workout, including a pool swim with no heart rate. HR-based TRIMP is a good second signal, provided swims use their own max heart rate.

Measure Inputs Run (GPS + HR) Pool swim, wrist HR Pool swim, no HR
Session RPE minutes + 0–10 rating ✅ ✅ ✅
Banister TRIMP HR, resting HR, max HR (per sport), sex ✅ ✅ with swim max HR ❌
rTSS / sTSS threshold pace / critical swim speed test ✅ (test needed) ✅ (test needed) ✅ (test needed)

Load measures: - Session RPE (Foster). Load = rating on Foster's 0–10 effort scale × session minutes [27][28]. In 12 well-trained swimmers over 20 sessions it correlated with HR-based load at r = 0.55–0.94 [29]. Verified Verified. It also supports simple "monotony" and "strain" warnings [27]. The weakness: the runner has to enter a rating, and the rating is subjective. - Banister TRIMP. The formula is duration × HRr × 0.64 × e^(1.92 × HRr), where HRr = (avg HR − resting HR)/(max HR − resting HR). The exponents are 1.92 for men and 1.67 for women [67][31]. Verified Verified. Using the full heart-rate trace rates interval sessions better than using average HR [32]. - Formula note: the peer-reviewed source leaves out the 0.64 (men) / 0.86 (women) multipliers. Only non-peer-reviewed sources give them [30][68]. This matters only if the app's numbers must match other tools. - Swim caveat: max heart rate in swimming is about 7 bpm lower than in running (6.7 ± 5.3 bpm, elite swimmers) [33]. An older study put the gap at about 12 bpm [34]. Verified Verified. Without a separate swim max HR, swim TRIMP comes out too low. - TSS family. rTSS, hrTSS and swim sTSS each need a threshold test (threshold pace or critical swim speed). TrainingPeaks cubes intensity for swims and calls its own method "simplistic" [35]. Other calculators square it instead [36]. HR-based scores differ between platforms [37]. No source validates adding run TSS and swim TSS into one number.

Models built on a load series: - Fitness/fatigue curves. CTL (fitness) and ATL (fatigue) track the last 42 and 7 days of load. TSB ("form") = CTL − ATL [38][39][69]. intervals.icu implements them as exponentially weighted averages [71]. Verified Verified. These can run on any daily load series, including session RPE. - ACWR (acute:chronic workload ratio). Impellizzeri and colleagues conclude that ACWR has no predictive advantage and that no study shows a causal effect on injury [40][70]. Lolli and colleagues show that the usual calculation creates a spurious correlation, because recent load is counted in both halves of the ratio [41]. Verified Verified. Other researchers find that this coupling issue has only trivial effects in practice [42][72]. The app should not present ACWR as an injury predictor.

What commercial tools do: - Strava Relative Effort (subscribers only) uses heart rate or perceived exertion, and weights activity types "so that your efforts can be compared across sports" [43]. - Garmin's acute load is a weighted sum of EPOC (excess post-exercise oxygen consumption) over recent days [44]. - Neither publishes its weights.

4. $0 hosting and browser storage

GitHub Pages or Cloudflare can host the app for $0. Browser storage is large enough, but Safari can delete it, so an export/import backup file and Add to Home Screen are required.

Cloudflare offers two hosting products, Workers and Pages. This research found no deprecation notice for Pages [49]. Netlify is the riskiest free host for a public demo.

Browser storage

  • Storage space is not a constraint. The browser's built-in storage (IndexedDB and OPFS) gets about 60% of disk per site in Chrome and Safari 17+. Firefox gets the smaller of 10% of disk or 10 GiB. localStorage is capped at 5 MiB [54][55]. OPFS works in about 97% of browsers [56].
  • Eviction is the real risk. Safari deletes "all … script-writeable storage" after 7 days without a visit to the site. Home Screen web apps are exempt [57][54].
    • Chrome and Safari grant or refuse navigator.storage.persist() silently; Firefox asks the user [54].
    • A WebKit bug reporting that persist() "always returns false" is still open [58], so Safari can't rely on it.
  • Backup. The File System Access API (save directly to a chosen file) works only in Chromium browsers [59]. The portable backup is therefore a plain download/upload file.
  • Libraries. Dexie.js (Apache-2.0) and idb (ISC) are both actively maintained as of September/October 2026 [60][61].

Cross-dimension insights

  1. Strava is the free bridge out of Apple's walled garden. Apple data can't reach a web app directly (§1), and the Strava API is paywalled (§2). But your Apple Watch workouts already land in Strava, and Strava's website returns the original file [18]. The route Apple Watch → Strava → Export Original → runner-app should cost nothing at any step, if free accounts keep export. Inference exported files that the user uploads are the user's own data, not "Strava API Data", so the API Policy's caching and AI rules should not apply. No Strava source confirms this.
  2. The swim requirement and the core intent point to the same input. Session RPE is a "how did that feel" rating (§3). Your brainstorm's core intent already relies on the runner as the only sensor of how they feel. One post-workout check-in (effort rating plus the body map) can drive both load tracking and injury warnings.
  3. Local-first privacy and Safari eviction are two sides of one design. Keeping data in the browser removes the account, server and privacy-breach risks (§4). The same choice makes the backup file the only copy outside the browser. That file can also feed the later "doctor-ready report" idea from your COULD list.
  4. Host risk follows from the LinkedIn plan. A post that gets attention brings a traffic spike. On Netlify's credit system, a spike pauses every site on the team [53]. GitHub Pages' soft limits [45] and Cloudflare's unlimited static requests [47] have no such cliff.

Contrary evidence

This run skipped the dedicated search for counter-evidence (the red-team pass). Points against the conclusions that turned up during research: - Session RPE depends on the user. It needs a rating after every session and is subjective [27]. If runners skip the rating, load for swims without heart rate goes missing. Strava's Relative Effort can use either heart rate or perceived exertion [43]. - The ACWR criticism has pushback. Other researchers find the coupling problem has only trivial effects in practice [42][72]. Even so, no study shows ACWR causally predicts injury [70].
