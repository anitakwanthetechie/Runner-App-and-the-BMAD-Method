MVP one-pager · working name

Runner App

“Most running apps cheer you on. This one gets you to the finish line, injury-free.”

Core intent

Help the runner train properly to the race plan and adapt it based on (1) how the runner feels and (2) race destination / route conditions.

Root need

Runners lack a personal, honest early-warning voice calibrated to their own body — apps cheer, nobody warns.

  • $0 build & hosting
  • Demoable online
  • Local-first, no sign-up
  • Human makes the final call
  • Readable, commented code

Scope as decided

MUST · MVP

Sprint 1

  1. Run upload + run log
  2. Training plan entry/upload + plan vs actual
  3. Race goal feasibility / projected finish
  4. No-race fitness view (HR zone 80/20 + fitness trend)
  5. Body map + mileage-ramp warning + see-a-pro escalation
  6. Trust basics: “Why?” on recommendations, local-first, no sign-up, $0 hosting

SHOULD

  • Basic calorie bank moved from MVP
  • Lightweight race profile: total elevation gain + expected race-day temperature promoted
  • A/B/C goals
  • Phase-aware fatigue context
  • Race week / Taper Jail
  • Carb-loading “upcoming withdrawals”

Design principles

  • Agents propose, the human decides. The BMAD agents build the app, but the Vibe CEO makes every final call. The same principle carries into the product: the app only offers recommendations, each with a “Why?” trail, and the runner decides.
  • Personal baselines over averages. Pain, fatigue, plans and fuel calibrate to the individual from day one.
  • Body map is the hub. One input powers injury warning, pain translator, Recovery Lap, Smart Skip and doctor report — model it well in Sprint 1.
  • Share the app, not the data. Data stays in the browser: private, near-zero compute, free.

Open questions & risks

  • $0 delivery. Web apps likely can’t read Apple Health and native iOS costs ~US$99/yr; free import paths (GPX/FIT/TCX, Strava API limits, free hosting tiers) still to verify.
  • Build agents drift. The BMAD agents’ output may diverge from requirements, with no clear explanation of chosen workflows.
  • Sharing at scale. How others upload data, privacy of their data, compute needs, whether anyone should pay.
